# Add dependencies and shadcn primitives

## Architecture Context

The build detail route and Now page rewrite require shadcn primitives that console-ui does not yet have, plus heavyweight libraries (`react-resizable-panels`, `@xyflow/react`, `@dagrejs/dagre`, `shiki`) consumed by the ported pipeline and detail-route components. Landing them in a dedicated foundational plan keeps the subsequent plans focused on UI logic and lets `pnpm install` run once before the UI rewrites.

Versions for Radix peer deps should be matched to the versions already in `packages/monitor-ui/package.json` for predictability.

## Implementation

### Overview

1. Add dependencies to `packages/console-ui/package.json`, matching semver to monitor-ui where applicable.
2. Add shadcn-style wrapper components under `packages/console-ui/src/components/ui/`. Each wrapper mirrors the equivalent monitor-ui shadcn file or the canonical shadcn template.
3. Re-export new wrappers from `packages/console-ui/src/components/ui/index.ts`.

This plan does not consume the new dependencies anywhere — that begins in plan-04.

### Key Decisions

1. **Match monitor-ui versions** for Radix peer deps to keep the dual-ship window predictable.
2. **Export every wrapper via `ui/index.ts`** so plan-04 onwards can import from a single barrel.
3. **No shadcn config tweaks.** Existing `tailwind` setup and `globals.css` tokens already support the components.

## Scope

### In Scope
- Update `packages/console-ui/package.json` to add the listed dependencies.
- Run `pnpm install` so the lockfile updates.
- Create shadcn wrapper files under `src/components/ui/`.
- Export the new wrappers from `src/components/ui/index.ts`.

### Out of Scope
- Wiring any component into pages or hooks.
- Theme changes.
- Tailwind config changes.
