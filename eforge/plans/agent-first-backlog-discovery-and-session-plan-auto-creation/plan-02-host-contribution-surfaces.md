# MCP, Pi, and CLI Contribution Surfaces

## Architecture Context

Coding-agent host integrations must be thin renderers over the shared `@eforge-build/client` contribution projection and formatting helpers from `plan-01-shared-contribution-projection`. MCP and Pi are the primary coding-agent paths; CLI must expose explicit full/detail modes for human and script debugging.

## Implementation

### Overview

Update the MCP tool, Pi tool/command, and CLI contribution commands to use compact list responses by default, expose list narrowing and show/detail options, render lists through shared budgeted formatters, and return smaller failed invocation envelopes.

### Key Decisions

1. Add `action: 'show'` to MCP and Pi tools for focused contribution detail; keep `invoke` behavior separate.
2. Use shared client list/detail formatting for broad responses instead of raw `JSON.stringify` in coding-agent hosts.
3. Fetch full detail only after a Pi interactive selection when schema data is needed for input prompts.
4. Keep CLI machine/debug use explicit through options such as `--full`, `--include-schema`, and `--include-diagnostics`.
5. Do not edit `eforge-plugin/` unless the Claude plugin version is bumped in the same change.

## Scope

### In Scope

- MCP `eforge_extension_contribution` list/show schemas for kind, extension name, search/id prefix, output profile, limit, offset, include schema, and include diagnostics.
- MCP host-safe list/show formatting and smaller failed invocation error payloads.
- Pi tool parity with MCP options and formatting.
- Pi `/eforge:extensions` list/detail rendering that avoids raw full manifests by default.
- CLI list/show options that expose compact default and explicit full/detail output.
- Reference docs/source docs updates for changed tool behavior.
- Host-surface tests that assert shared helpers are used and raw manifests are not dumped by default.

### Out of Scope

- Shared projection implementation; that is handled in `plan-01-shared-contribution-projection`.
- eforge-plan backlog action payload changes.
- Workstation planning-task auto-apply.

## Implementation Notes

- Pi interactive browsing can list compact entries first, then call the shared detail helper with `includeInputSchema: true` for the selected contribution before `prepareContributionInput` runs.
- For MCP list/show responses, return text generated by shared formatting helpers rather than pretty-printing raw objects.
- For MCP and Pi failed invocations, return the summarized failure envelope and set MCP `isError: true` through `McpUserError`.
- Keep `requestedBy.host` values unchanged: `mcp`, `pi`, and `cli`.
- If docs generation changes generated files, run `pnpm docs:generate` and commit generated artifacts.
