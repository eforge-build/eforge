# Analyze-All Evidence Integration and Recommendation Overlay

## Architecture Context

This plan wires the shipped-evidence provider into `analyze-all-backlog` before the daemon planning task is started. The planning model receives compact, labeled candidates and instructions that only strong cited evidence can produce shipped-status patches. The apply path also enforces a deterministic status overlay so recommendations generated by the same curation draft do not continue to reference items proposed as closed.

This plan depends on `plan-01-shipped-evidence-provider`.

## Implementation

### Overview

Extend `buildBacklogCurationSource` to collect shipped evidence for open items, include bounded strong/ambiguous candidates in `sourceText`, include a stable projection in the source fingerprint, update the curation prompt, and filter generated recommendations through proposed closed-status item changes before validation/write.

### Key Decisions

1. **Evidence affects source fingerprint.** Include a compact stable evidence projection in the curation source fingerprint so a new reachable merge/PR evidence change starts a fresh analyze-all task.
2. **Weak evidence stays out of model context.** Keep weak candidates available in provider tests/diagnostics, but only include strong and ambiguous candidates in `source.shippedEvidenceCandidates`.
3. **Lifecycle evidence remains highest confidence.** Lifecycle-derived shipped candidates are labeled separately and ranked before git/PR-inferred candidates.
4. **Recommendation overlay is deterministic.** The apply path filters recommendation target arrays using draft item/epic status changes before validation and before writing `current.json`.

## Scope

### In Scope

- Invoke shipped-evidence collection during analyze-all source assembly for visible open items.
- Include compact `shippedEvidenceCandidates`, candidate counts, diagnostics, and truncation counters in source context.
- Include evidence candidates in source fingerprint projection.
- Update prompt instructions for strong shipped proposals, ambiguous needs-input/skipped routing, evidence labels, and same-draft recommendation exclusion.
- Add a backend recommendation overlay helper that removes proposed closed item/epic references from generated recommendations before validation/write.
- Add regression tests for source inclusion, PR-unavailable fallback, context caps, recommendation filtering, and prompt guidance.

### Out of Scope

- Workstation visual rendering changes.
- New daemon routes or client route shapes.
- Automatic curation apply.
- Persistent PR metadata caching.

## Implementation Notes

- Add an optional third parameter to `buildBacklogCurationSource(cwd, redraft?, options?)` rather than changing existing call sites that pass only `cwd` or `redraft`.
- Keep `source.shapedEvidenceCandidates` out of the plan; use `source.shippedEvidenceCandidates` as the field name so tests and prompt guidance refer to one stable name.
- Candidate projection in the fingerprint must include deterministic fields only: item id/title, source, confidence, PR number/title/branch when present, merge short hash/subject when present, changed paths, and citations. Do not include timestamps from collection time.
- The model-context evidence payload must cap candidates, citations, paths, excerpts, and diagnostics. Add truncation counters for omitted candidates/excerpts/paths.
- Evidence strings requested from the model must use exact prefixes:
  - `Shipped evidence: lifecycle trace — ...`
  - `Shipped evidence: inferred from git/PR history — ...`
  - `Ambiguous shipped candidate: needs input — ...`
- The recommendation overlay must remove proposed shipped item ids from `activeWork`, `readyCandidates`, `recommendedNextSequence`, `safeParallelizableGroups.itemIds`, `blockedChains.itemIds`, and `blockedChains.blockedBy`; it must remove proposed closed epic ids from `safeParallelizableGroups.epicIds`.
- Drop safe-parallel groups whose `itemIds` become empty. Drop blocked chains whose `itemIds` become empty. Preserve `rationaleAndAssumptions` and append a concise filtering note when any target is removed.
