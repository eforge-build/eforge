# Validation Provider Recovery Documentation

## Architecture Context

Plan 01 changes validation-provider failures from immediate terminal plan gates to fail-closed gates with bounded in-plan recovery for normal quality-gate failures. Public extension docs and SDK comments need to describe recoverable versus hard failures without adding a new public configuration knob.

## Implementation

### Overview

Update extension SDK comments, API docs, guide docs, examples, and package README/reference copies to match the new validation-provider failure semantics.

### Key Decisions

1. Describe providers as fail-closed gates: normal failures can be repaired first, but unresolved failures still emit `plan:build:failed`.
2. Document the hard-failure boundary: thrown exceptions, timeouts, and unexpected return shapes bypass recovery.
3. Document annotations as the path to precise recovery issues.
4. Regenerate public docs artifacts instead of hand-editing generated mirrors.

## Scope

### In Scope

- SDK type comments for `registerValidationProvider` and `ValidationProviderResult`.
- Root extension guide and API reference.
- Public web guide/API reference source copies.
- Package README/reference docs for extension SDK runtime status and validation-provider semantics.
- Validation-provider example comments and example README language.
- Generated public docs artifacts produced by `pnpm docs:generate`.

### Out of Scope

- New SDK fields or configuration options.
- Client event schema documentation for new events.
- Plugin or Pi integration changes.
- Final validation command docs.

## Documentation Requirements

- State that legacy non-empty string failures, structured `{ status: 'failed' }` results, and command-form non-zero exits enter the recovery loop.
- State that provider throws/rejections, provider timeouts, and unexpected return shapes emit terminal `plan:build:failed` without recovery.
- State that recovery uses the plan's review-fixer/evaluator path and `review.maxRounds` budget.
- State that after a recovery attempt, the provider suite reruns from the first provider.
- State that unresolved recoverable failures still fail the plan.
- State that structured annotations improve file/line targeting for recovery.
- Do not document a public `failurePolicy` option.
